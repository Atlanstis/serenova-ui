# ui-quality-pipeline Specification

## Purpose

定义 Serenova UI 在持续开发和发布前必须通过的分层 UI 质量验证，以覆盖公共契约、真实浏览器行为、视觉稳定性和包消费能力。

## Requirements

### Requirement: 每个公共组件具备快速行为测试

每个公共组件 MUST 具有面向 Props、Slots、Events、渲染输出和状态变化的快速组件测试，测试 SHALL 聚焦公共接口而非内部响应式状态或私有方法。

#### Scenario: 重构组件内部实现

- **WHEN** 维护者改变组件内部组织但保持公共行为不变
- **THEN** 面向公共契约的测试继续通过且无需访问组件实例内部字段

### Requirement: 浏览器相关行为在真实浏览器中验证

依赖原生表单、布局或计算样式的行为 MUST 在真实浏览器组件测试中验证，且首阶段 CI SHALL 至少使用 Chromium。

#### Scenario: 验证 Button 表单和布局

- **WHEN** 浏览器测试使用 `SButton` 提交或重置表单并检查块级尺寸
- **THEN** 测试能够观察原生表单行为和真实布局结果

### Requirement: 关键视觉状态具有回归基线

公共组件的稳定视觉状态 SHALL 具有截图回归基线，基线 MUST 在固定浏览器、操作系统、字体、视口和动画策略下生成与比较。

#### Scenario: Button 样式意外变化

- **WHEN** Button 状态矩阵的实际截图超出允许差异
- **THEN** 视觉回归检查失败并提供可审查的差异结果

### Requirement: 不以结构快照替代行为断言

测试套件 MUST NOT 将完整 HTML 快照作为组件正确性的唯一证明；任何结构快照 SHALL 与明确的行为或语义断言配合使用。

#### Scenario: 组件存在完整 HTML 快照

- **WHEN** 测试使用完整组件结构快照
- **THEN** 同一行为范围还存在针对用户可见结果、事件或语义属性的明确断言

### Requirement: 验证发布产物可消费

发布前质量流程 MUST 使用构建产物完成包级冒烟检查，验证包根入口、样式入口、默认插件、具名导出和类型声明可被消费项目解析。

#### Scenario: 源码测试通过但导出映射错误

- **WHEN** 源码测试全部通过但构建产物无法从公共入口解析
- **THEN** 包级冒烟检查失败并阻止发布

### Requirement: 提供统一的 CI 质量入口

仓库 SHALL 提供可重复执行的命令以运行类型检查、快速测试、浏览器测试、视觉回归、构建和包级检查，其中任一必需步骤失败 MUST 导致 CI 失败。

#### Scenario: 提交包含 UI 回归

- **WHEN** CI 执行统一质量入口且任一必需测试检测到回归
- **THEN** 质量流程返回失败状态并阻止该提交进入发布流程
