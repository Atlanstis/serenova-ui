# ui-quality-pipeline Specification

## Purpose

定义 Serenova UI 在持续开发和发布前必须通过的分层 UI 质量验证，以覆盖公共契约、真实浏览器行为、视觉稳定性和包消费能力。

## Requirements

### Requirement: 测试工作区按对象与职责组织

仓库 MUST 将自动执行的测试用例与共享测试基础设施明确分区，组件测试 SHALL 按组件领域聚合，并 SHALL 使用 `*.unit.spec.ts`、`*.integration.spec.ts` 和 `*.e2e.spec.ts` 分别标识快速单元测试、真实浏览器集成测试和 Playwright E2E 测试。发布包契约测试 SHALL 保持独立分区，作为独立于上述三层的包级验证。

#### Scenario: 为新公共组件添加测试

- **WHEN** 维护者为新的公共组件建立测试资产
- **THEN** 该组件的单元测试、适用的集成测试和局部 Fixture 按组件领域共置，代表性 E2E 按用户流程组织

#### Scenario: 添加跨用例测试辅助

- **WHEN** 多个组件、集成测试或 E2E 流程需要共享 setup、helper 或 Fixture
- **THEN** 共享资产进入对应测试支持区域，并使用测试运行器约定之外的辅助文件命名

### Requirement: 组件开发遵循统一测试完成基准

仓库的贡献者规则 MUST 面向所有公共组件定义测试目标和分层选择条件。每个公共组件变更 MUST 分析 Props 及默认值、Slots、Events、渲染语义、交互状态、边界条件、源码类型和公共导出，MUST 完成适用测试，并 MUST 记录单元、集成、E2E 和发布契约测试的选择结论与验证结果。

#### Scenario: 自动化代理实现新的公共组件

- **WHEN** 自动化编码代理新增或改变公共组件
- **THEN** 代理从该组件自身的公共契约推导单元测试，并依据浏览器依赖和代表性用户流程决定是否补充集成测试或 E2E

#### Scenario: 选择组件测试层

- **WHEN** 维护者分析公共组件的行为、运行环境依赖和消费流程
- **THEN** 变更记录列出各测试层是否适用、对应公共契约及实际验证结果

### Requirement: 每个公共组件具备快速行为测试

每个公共组件 MUST 具有面向自身公共契约的快速黑盒单元测试。测试 SHALL 根据适用性覆盖 Props 及默认值、Slots、Events、可观察渲染结果、状态变化、语义属性、边界条件、源码类型和单组件公共导出，测试输入与断言 MUST 基于公共接口和用户可观察结果，验证范围 MUST 限于公共契约。

#### Scenario: 重构组件内部实现

- **WHEN** 维护者改变组件内部组织但保持公共行为不变
- **THEN** 单元测试继续通过，并通过公共接口与用户可观察结果验证行为

#### Scenario: 新组件具有不同公共契约

- **WHEN** 维护者新增一个具有不同 Props、Slots、Events、类型或交互模型的公共组件
- **THEN** 单元测试从该组件自身契约推导覆盖范围，形成与其契约匹配的用例集合

### Requirement: 浏览器相关行为在真实浏览器中验证

公共契约涉及原生表单、真实焦点与键盘、浏览器事件、Teleport、滚动与溢出、响应式布局、元素尺寸、计算样式或多个组件协作时，仓库 MUST 增加真实浏览器集成测试；集成测试的适用性 SHALL 仅由上述公共契约决定。首阶段集成测试 SHALL 至少使用 Chromium，关键视觉契约 MUST 使用少量稳定的布局或计算样式断言验证。

#### Scenario: 验证浏览器原生行为

- **WHEN** 公共组件依赖原生表单、真实焦点、键盘或其他浏览器事件
- **THEN** 集成测试通过用户操作和可观察结果验证行为，并在鼠标与键盘触发同一操作时验证一致的业务结果

#### Scenario: 验证组件协作

- **WHEN** 一个公共行为依赖多个组件、Teleport 目标或共享上下文共同工作
- **THEN** 集成测试在真实浏览器中挂载最小必要组件组合并验证整体公共行为

#### Scenario: 验证 Button 表单和布局

- **WHEN** 集成测试使用 `SButton` 提交或重置表单并检查通过 style 设置的按钮宽度
- **THEN** 测试能够观察原生表单行为和真实布局结果

#### Scenario: 验证关键布局或样式契约

- **WHEN** 尺寸、定位、溢出、响应式布局或计算样式属于组件的公共契约
- **THEN** 集成测试使用稳定且聚焦的断言验证相关结果

### Requirement: 结构快照配套行为断言

测试套件 MUST 通过明确的行为或语义断言证明组件正确性；任何结构快照 SHALL 与这些断言配合使用。

#### Scenario: 组件存在完整 HTML 快照

- **WHEN** 测试使用完整组件结构快照
- **THEN** 同一行为范围还存在针对用户可见结果、事件或语义属性的明确断言

### Requirement: 验证发布产物可消费

发布前质量流程 MUST 使用构建产物完成独立的包级契约检查，验证包根入口、自动样式和公共入口范围、默认插件、具名导出、类型声明、模块格式和 npm 文件边界可被消费项目解析。该检查 SHALL 与浏览器 E2E 分工，静态发布契约 SHALL 由包级检查独立验证。

#### Scenario: 源码测试通过但导出映射错误

- **WHEN** 源码测试全部通过但构建产物无法从公共入口解析
- **THEN** 发布契约测试失败并阻止发布，无论浏览器 E2E 是否通过

#### Scenario: 浏览器流程通过但包内容越界

- **WHEN** E2E 使用的构建产物可以运行但 npm 包包含约定范围以外的文件
- **THEN** 发布契约测试失败并明确报告文件边界问题

### Requirement: 提供统一的 CI 质量入口

仓库 SHALL 提供快速日常检查和完整质量检查两个可重复执行的入口。快速检查 MUST 包含单元测试；完整质量检查 MUST 包含类型检查、单元测试、真实浏览器集成测试、基于构建产物的代表性 Playwright E2E、构建和独立发布契约测试，其中任一必需步骤失败 MUST 导致流程失败。Storybook SHALL 仅承担开发工作台职责，完整质量检查 SHALL 由上述独立验证步骤组成。

#### Scenario: 日常执行快速反馈

- **WHEN** 维护者运行日常检查入口
- **THEN** 流程仅执行静态检查和快速单元测试

#### Scenario: 提交包含公共行为回归

- **WHEN** 完整质量检查执行且任一必需测试检测到公共行为、浏览器契约、消费流程或包消费回归
- **THEN** 质量流程返回失败状态并阻止该变更进入发布流程

#### Scenario: 提交包含 UI 回归

- **WHEN** 完整质量检查执行且任一必需测试检测到 UI 公共行为、真实浏览器契约或代表性消费流程回归
- **THEN** 质量流程返回失败状态并阻止该提交进入发布流程

### Requirement: 通过最小消费应用验证代表性 E2E 流程

仓库 MUST 提供一个通过公共包入口加载构建产物且默认通过组件使用自动加载样式的最小消费应用，并 MUST 使用 Playwright 验证代表性的关键用户流程。E2E SHALL 按代表性关键用户流程组织，其适用性 SHALL 由消费流程覆盖需求决定；首阶段 SHALL 使用 Chromium，仅在出现明确浏览器兼容风险时扩展 Firefox 或 WebKit。

#### Scenario: 验证构建产物的真实消费流程

- **WHEN** 完整质量检查运行代表性 E2E
- **THEN** 消费应用加载当前构建产物，完成公共安装与自动样式加载，并分别覆盖包根、组件子路径及插件使用，并通过用户可观察结果验证关键交互流程

#### Scenario: 新增简单公共组件

- **WHEN** 新组件的行为已由单元测试及适用的集成测试充分覆盖，且没有引入新的关键用户流程
- **THEN** 维护者可保持现有 E2E 用例集合，并在变更记录中将该组件专属 E2E 标记为“豁免”，说明现有单元测试及适用集成测试的覆盖依据

### Requirement: 长期组件规则仅面向客户端

AGENTS.md MUST 明确当前及后续公共组件的设计、实现、适配、公共 API 和渲染测试范围仅限浏览器客户端。测试 MUST 覆盖适用的客户端主题隔离、Teleport、键盘交互及独立包契约。Node 环境验证 MUST 仅覆盖模块加载和发布契约。E2E 规则 MUST 以公共 JavaScript 入口导入组件并自动加载样式作为默认接入流程。

#### Scenario: 新组件设计

- **WHEN** 贡献者依据 AGENTS.md 设计新的公共组件
- **THEN** 仅规划客户端渲染能力，分析客户端公共契约并完成适用测试层

#### Scenario: 验证客户端与模块加载边界

- **WHEN** 执行完整质量检查
- **THEN** 渲染用例仅验证客户端行为，Node 模块加载由独立包契约测试验证
