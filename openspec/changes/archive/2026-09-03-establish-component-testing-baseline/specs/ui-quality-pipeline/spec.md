## ADDED Requirements

### Requirement: 测试工作区按对象与职责组织

仓库 MUST 将自动执行的测试用例与共享测试基础设施明确分区，组件测试 SHALL 按组件领域聚合，并 SHALL 通过稳定的文件命名约定标识运行环境，使每个公共组件的测试资产可以从单一组件领域定位。

#### Scenario: 为新公共组件添加测试

- **WHEN** 维护者为新的公共组件建立测试资产
- **THEN** 该组件的快速测试、真实浏览器测试和局部 Fixture 位于同一组件领域，运行器能够仅依据约定后缀发现适用用例

#### Scenario: 添加跨用例测试辅助

- **WHEN** 多个组件或集成测试需要共享 setup 或 helper
- **THEN** 共享资产进入测试支持区域，并使用测试运行器约定之外的辅助文件命名

### Requirement: 组件开发遵循统一测试完成基准

仓库的贡献者规则 MUST 面向所有公共组件定义测试目标和分层选择条件。每个公共组件变更 MUST 分析 Props、Slots、Events、渲染语义、交互状态、边界条件和导出契约，MUST 完成适用测试，并 MUST 记录各测试层的选择结论。

#### Scenario: 自动化代理实现新的公共组件

- **WHEN** 自动化编码代理新增或改变公共组件
- **THEN** 代理从该组件自身的公共契约推导测试范围并完成适用测试

#### Scenario: 选择组件测试层

- **WHEN** 维护者分析公共组件的行为与运行环境依赖
- **THEN** 变更记录列出选用的测试层、对应公共契约及验证结果

## MODIFIED Requirements

### Requirement: 每个公共组件具备快速行为测试

每个公共组件 MUST 具有面向自身公共契约的快速黑盒测试。测试 SHALL 根据适用性覆盖 Props 及默认值、Slots、Events、可观察渲染结果、状态变化、语义属性和边界条件，测试输入与断言 MUST 基于公共接口和用户可观察结果。

#### Scenario: 重构组件内部实现

- **WHEN** 维护者改变组件内部组织但保持公共行为不变
- **THEN** 面向公共契约的测试继续通过，并通过公共接口与用户可观察结果验证行为

#### Scenario: 新组件具有不同公共契约

- **WHEN** 维护者新增一个与现有组件具有不同 Props、Slots、Events 或交互模型的公共组件
- **THEN** 快速测试从该组件自身契约推导覆盖范围并验证对应行为

### Requirement: 浏览器相关行为在真实浏览器中验证

依赖原生表单、焦点与键盘交互、浏览器事件、布局、视口或计算样式的公共行为 MUST 在真实浏览器组件测试中验证，且首阶段质量流程 SHALL 至少使用 Chromium。关键视觉契约 MUST 使用少量稳定的布局或计算样式断言验证。

#### Scenario: 验证浏览器原生行为

- **WHEN** 公共组件依赖浏览器原生表单、焦点、键盘或其他 DOM 行为
- **THEN** 真实浏览器测试能够通过用户可观察结果验证该行为

#### Scenario: 验证 Button 表单和布局

- **WHEN** 浏览器测试使用 `SButton` 提交或重置表单并检查块级尺寸
- **THEN** 测试能够观察原生表单行为和真实布局结果

#### Scenario: 验证关键布局或样式契约

- **WHEN** 尺寸、定位、溢出、响应式布局或计算样式属于组件的公共契约
- **THEN** 真实浏览器测试使用稳定且聚焦的断言验证相关结果

### Requirement: 提供统一的 CI 质量入口

仓库 SHALL 提供可重复执行的命令以运行类型检查、快速测试、真实浏览器测试、Storybook 预览集成测试、构建和包级检查，其中任一必需步骤失败 MUST 导致质量流程失败。

#### Scenario: 提交包含公共行为回归

- **WHEN** 质量流程执行且任一必需测试检测到公共行为、浏览器契约、预览环境或包消费回归
- **THEN** 质量流程返回失败状态并阻止该变更进入发布流程

#### Scenario: 提交包含 UI 回归

- **WHEN** 质量流程执行且任一必需测试检测到 UI 公共行为或浏览器契约回归
- **THEN** 质量流程返回失败状态并阻止该提交进入发布流程

## REMOVED Requirements

### Requirement: 关键视觉状态具有回归基线

**Reason**: 质量流程改用真实浏览器中的聚焦布局与计算样式断言，为当前组件规模提供稳定、可执行的视觉契约验证。

**Migration**: 删除现有截图用例、截图专用配置与命令；将属于公共契约的尺寸、布局和计算样式迁移为聚焦的真实浏览器断言。未来在组件视觉结构稳定并具备固定执行环境、版本化基线和差异审查流程后，通过独立变更重新引入截图回归。
