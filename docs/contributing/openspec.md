# OpenSpec 使用规范

使用 OpenSpec 技能前须阅读对应的 `SKILL.md`。本规范补充仓库默认行为，用户明确指令优先。

## 同步后自动清理

用户直接调用 `openspec-sync-specs`，且满足以下全部条件时，无需再次确认，默认执行“同步主规格 → 校验 → 删除变更目录 → 生成 Git 提交信息”：

- 选定的 OpenSpec 根目录中，只有一个待同步的活动变更（可包含多个增量规格；是否待同步依据与主规格的语义差异判断）
- 技能调用后附带的完整变更名称与该变更名称完全一致
- 用户未要求保留变更、归档或仅同步部分规格

执行时遵守以下约定：

- 按技能完成全部增量规格的同步，并通过 `openspec validate --specs`；根目录、store 和增量路径沿用技能解析结果
- 清理前说明目标目录；仅删除所选根目录内的 `openspec/changes/<change-name>/`，不归档，不删除主规格、其他变更或符号链接指向的外部内容
- 同步或校验失败、仍有未完成任务、未解决问题（含 TBD Purpose）或需要保留的独有资料时，保留变更目录并说明原因
- 不满足触发条件或无法确认条件时，按技能原流程处理并保留变更目录；归档流程间接调用同步时不适用本规则

本规则明确覆盖技能默认的“同步后保留活动变更”行为。

## Git 提交信息

自动同步与清理完成后，汇总同步内容、删除目录和校验结果，并按 [提交规范](commits.md) 提供基于本次实际差异的提交信息。仅生成文本；除非用户另有授权，不执行 `git add`、`git commit` 或 `git push`。
