# 组件测试规范

- 新增或修改公共组件时，必须先分析该组件的 Props 及默认值、Slots、Events、渲染语义、交互状态、边界条件、源码类型和公共导出，并从这些公共契约推导测试范围，不得复制其他组件的固定用例集合代替分析。
- 每个公共组件必须在 `tests/components/<组件领域>/` 中具有 `*.unit.spec.ts` 快速黑盒单元测试，并根据适用性验证公共输入、用户交互、可观察输出、状态变化、源码类型和单组件公共导出。
- 单元测试的输入与断言必须基于公共接口和用户可观察结果；不得通过访问内部状态、调用私有方法或断言非契约实现结构证明组件正确性。
- 公共契约涉及原生表单、真实焦点与键盘、浏览器事件、Teleport、滚动与溢出、响应式布局、元素尺寸、计算样式、多个组件或共享上下文协作时，必须增加由 Vitest Browser Mode 执行的 `*.integration.spec.ts` 真实浏览器集成测试；不涉及这些条件时，不得仅为满足数量要求而增加集成测试。
- 集成测试必须挂载验证契约所需的最小 Fixture；鼠标与键盘触发同一操作时，必须通过用户可观察结果验证两种输入获得一致的业务行为。
- Playwright E2E 必须使用最小消费应用，通过公共 JS 入口加载当前 `dist` 构建产物；不得显式导入组件库 CSS，组件库不提供独立 CSS 入口，并按代表性关键用户流程组织；不得要求每个公共组件单独具有 E2E。
- 新增或修改的流程涉及多个公共组件、全量或按需安装与全局样式、关键表单或浮层操作链路，或者可能造成高影响消费回归时，必须评估并按需增加 `*.e2e.spec.ts`；首阶段仅要求 Chromium，只有出现明确兼容性风险时才扩展其他浏览器。
- `tests/contracts/package/` 中的发布契约测试独立于单元、集成和 E2E 三层，必须继续验证构建产物的 ESM、类型声明、自动样式、插件、导出映射和 npm 文件边界，并确认无 CJS 产物及 `require` 入口；不得以浏览器 E2E 替代这些检查。
- Storybook 仅用于开发预览、交互调试和组件文档，不作为自动化测试载体或发布质量门槛；Story 的存在和 `play` 函数不得替代组件公共行为测试。
- 公共组件或类型导出发生变化时，必须同步更新源码出口测试和共享包消费 Fixture。
- 单个组件或用例使用的 Fixture 必须与所属测试共置；跨组件复用的 setup、helper 或 Fixture 必须放入 `tests/support/`，E2E 消费应用及其专用资产必须放入 `tests/e2e/`。
- 结构快照投入使用时必须与明确的行为或语义断言配套，不得作为正确性的唯一证明。
- 组件任务完成前必须记录 unit、integration、E2E 和 package 各层是否适用及理由，并运行测试类型检查和所有受影响的 `test:unit`、`test:integration`、`test:e2e`、`test:package` 质量命令，在变更说明中记录验证结果。
